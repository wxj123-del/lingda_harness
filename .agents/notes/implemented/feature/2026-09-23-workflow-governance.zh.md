# Agent Note：工作流治理与重试控制

Status: implemented

[English](2026-09-23-workflow-governance.md) | 中文

## Problem

直接工作流控制台已经支持运行控制，但图执行仍缺少节点重试策略、严格的流程节点数量校验和可配置运行超时。内置模板也需要生成可执行的分支图，而不只是展示用卡片。

## Decision

工作流节点现在可以保存有上限的重试次数。编译器会为模型节点和条件节点生成重试循环，并通过现有 `log()` 钩子报告重试进度、节点开始/完成和条件分支结果。编辑器校验与编译器保持一致，检查可达性、终点路径、标识唯一性和分支连接。内置模板导入后会得到可执行的图，其中内容审核模板包含双向分支，并保留第一版发布快照。输出节点支持模板替换和 JSON 解析。直接测试运行支持保存文本或 JSON 输入，以及 1 秒到 24 小时的可选超时。Host 继续负责输入、结果、错误、元数据和并发上限。

## Alternatives considered

把重试和图检查交给各节点会导致编辑器与编译器契约漂移；全局重试策略又无法让作者在瞬态操作处显式、有限地配置恢复，因此均未采用。

## Consequences

工作流作者可以让暂时性的模型或条件失败在节点级恢复，不需要改动 Host 引擎。输出节点支持模板替换和 JSON 解析。重试策略必须显式配置，不会吞掉基础设施异常。超时仍由 Host 持有并负责取消和清理。

## Validation

UI Layout 和 Session Controller TypeScript 检查通过。工作流编译器和面板测试通过 17 个用例。Remote Client TypeScript、bundle、客户端 UI locale 校验和 `git diff --check` 均通过。
