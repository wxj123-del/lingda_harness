# Agent Note: 上下文路由中的持久压缩摘要保留

Status: implemented

[English](2026-09-23-context-checkpoint-routing.md) | 中文

## Problem

上下文路由会从请求快照中移除较早消息，即使压缩流程已经生成了包含任务决策和当前状态的持久摘要。

## Decision

对于 `recent` 和 `task` 路由，路由器会把当前生效的最新压缩摘要作为必选消息保留，即使它位于配置的消息尾部之外。明确的 `fresh` 路由会排除该摘要，因此声明切换话题时仍保持隔离。摘要继续使用统一 Token 计量；如果必选系统提示词和当前请求已经占满预算，保留摘要可能使请求有意超过预算。

## Alternatives considered

**只依赖最近消息尾部。** 否决原因：压缩后如果继续执行很长的工具链，摘要会在任务结束前被推到尾部之外。

**所有路由都保留摘要。** 否决原因：`fresh` 是明确的隔离请求，不应继承旧任务记忆。

**增加第二套任务记忆存储。** 暂缓原因：压缩摘要已经持久化、可被模型看到并可重放；在语义召回实现前增加第二套存储会复制状态。

## Consequences

长任务无需发送完整 transcript 也能继续读取最新持久决策。新话题路由仍保持隔离。路由器依赖压缩摘要谓词，摘要保留情况通过已有的选中消息审计体现，不增加新的事件类型。
