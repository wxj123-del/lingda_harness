# Agent Note: 可选的逐次请求 Token 轨迹

Status: implemented

[English](2026-09-16-token-trace-plugin.md) | 中文

## 问题

普通轨迹侧重内容和时间。用户需要将每次已记录的模型尝试及其输入来源与供应商用量一同检查，包括没有生成可见助手消息的失败尝试。

## 决定

可选的 `dsh-client-ui-step-insight` 组合包通过插槽优先级替换 `trajectory` 会话视图。它通过私有渲染器 hook 读取现有会话事件窗口，并保持原轨迹目标拥有者运行。卸载插件后恢复原视图。安装不改变随附默认配置、模型提示词或持久化格式。

供应商用量与内容估算保持分离。缺失的缓存字段不会变成零。完整且一致的供应商总量是精确值；否则已知字段之和明确标为下界。思考保持为输出的子集。每次持久尝试独立成行，实时用量检查点替换而不累计，持久结算替换临时流内容。压缩用量独立成行。输入检查应用内容替换并保留事件编号，但不虚构自定义消息投影或压缩提示词。

工具定义显示与所选请求中保留的用户文本的本地词项相似度，默认参照最新用户消息。词项去重和 IDF 加权余弦比较避免重复词抬高相关度；有限的中英任务词表连接常见请求和英文描述。工具侧仅使用名称和描述。界面展示参照消息、匹配词、实际调用标记及可选的降序排列，与 Token 估算相互独立。文本不会发送给其他模型。

## 考虑过的替代方案

**扩展现有轨迹记录布局。** 其按步骤组织的助手状态不足以独立保留每次失败尝试。可选替换视图可以读取持久尝试，而不改变其他使用方。

**为每条消息分配精确的供应商输入份额。** 提供方返回汇总计数，没有逐消息分词依据。按比例分配会呈现无依据的精确性，因此插件展示文本估算和原始汇总。

**使用向量或额外模型计算相关度。** 这会为用量检查增加模型配置、延迟及可能的计费用量。用户选择本地文本比较，通过明确的估算标记和匹配依据展示结果，不宣称语义置信度。

## 影响

视图仅统计已加载历史，明确排除子会话及没有用量事件的辅助调用。工具结果可在保留它的每次后续请求中查看，但工具执行和 PTC 内部结果不会产生额外的供应商计数。完整源记录可以导出。

现有[输入框统计决策](2026-09-07-composer-session-stats-pills.zh.md) 继续定义完整会话合计，本记录不取代它。[会话组装决策](../architecture/2026-08-09-client-conversation-node-assembly.zh.md) 继续定义目标和注册。

## 验证

针对性测试覆盖缓存计量、缺失字段、重试、临时流结算、中断、压缩、输入替换、分页、交互和卸载。无密钥浏览器用例以可选配置层启动真实组合，加载既有会话录制，验证搜索、检查和导出，并检查桌面与移动布局。

相似度测试覆盖中英文任务、无关和缺失文本、重复词、排除内容、历史截止点与替换、排序、参照选择及实际调用标记。浏览器用例为录制中的工具定义占位符提供具体定义，检查可见的相关度控件、匹配依据和窄屏布局，并保留原供应商计量。
