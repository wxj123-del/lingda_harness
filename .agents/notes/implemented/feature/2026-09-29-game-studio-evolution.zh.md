# Agent Note: 基于证据的游戏工作室演进

Status: implemented

[English](2026-09-29-game-studio-evolution.md) | 中文

## Problem

游戏工作室的 checkpoint 和发布报告能保留单次运行发生的事实，但后续运行无法区分可复用经验、模型回忆和一次性项目事实。若一次运行就自动改写内置 Skill，会把未经证实的指导扩散到其他项目，也难以追踪回归来源。

## Decision

`studio_evolve` 使用 `.game-studio/evolution/observations/<rule-id>/<run-id>.json` 下的不可变观察维护项目级 playbook。每条观察都会读取已经保存的发布报告，并复制具名证据和源码修订。支持性观察要求报告为 `READY` 且引用的检查均已通过；反证观察要求报告为 `BLOCKED` 且至少引用一个失败检查。

运行时将每条规则计算为 `TRIAL`、`ACTIVE` 或 `CONTESTED`。达到可配置数量的独立支持运行后，指导才会激活；任何反证都会将其隔离。游戏工作室提示词会在 `SCAN` 阶段载入该 playbook，只自动采用已激活指导，并保持内置 Skill 不可变。将单一项目经验晋升到内置 Skill 仍需受审查的源码变更和跨项目证据。

## Alternatives considered

**允许模型在每次运行后改写内置 Skill。** 不采用，因为一次虚假的因果判断或项目特有变通就会在没有审查与回滚证据的情况下影响无关项目。

**只保存自由文本复盘。** 不采用，因为普通文本无法验证经验对应的源码修订、发布结论或具名检查，也无法机械判断指导何时适合复用。

**每条项目级规则都要求人工批准。** 不采用，因为同一工作区内多次经过验证的运行可以形成有用的自动阈值；跨项目晋升到随附 Skill 时仍保留人工审查。

## Consequences

后续运行能够复用经过多次发布证据支持的指导，失败证据则会阻止自动复用。每个运行使用独立不可变文件，既避免并发聚合写入，也保留当时的完整证据快照。该机制只能建立证据相关性，不能证明因果，因此激活阈值可配置，内置 Skill 变更仍处于自动闭环之外。
