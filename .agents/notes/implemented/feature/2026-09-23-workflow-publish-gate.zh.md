# Agent Note：工作流发布门禁

状态：已实现

[English](2026-09-23-workflow-publish-gate.md) | 中文

## 问题

编辑器虽然已经展示草稿和已发布状态，但启用的草稿工作流仍会被注册成普通对话工具。后续加入版本历史后，还需要明确已有线上版本、同时存在未发布修改时应执行哪一版。

## 决策

工作流工具注册现在要求工作流已启用且存在可发布内容。已发布记录暴露当前图；带版本历史的草稿暴露最新不可变快照；没有线上版本的新草稿不会注册。目录页的状态徽标和对话按钮使用同一个判断逻辑。没有生命周期字段的旧记录为保持兼容仍可运行。

编辑器只比较发布内容（名称、描述、执行说明、流程图和派生步骤）与最新线上版本。保存或测试修改后的发布内容时，会持久化为草稿并继续保留上一版快照在线。测试输入、超时、启用状态和画布视口不会改变发布状态。复制的工作流始终从未发布草稿开始，不携带版本或测试输入。

## Alternatives considered

注册每个启用的 draft 会让未完成的图变更进入普通对话；每次保存都替换线上 release 则无法保留可审查的 draft 边界，因此均未采用。

## 结果

用户可以编辑和测试未完成的流程，而不会把未发布的图暴露给普通对话，也不会让上一线上版本下线。发布仍是替换模型/工具执行内容的唯一边界；禁用工作流仍会将其从工具注册表移除。

## 验证

工作流面板、布局加载和编译器测试通过。Client UI TypeScript、国际化校验以及 `git diff --check` 通过。
