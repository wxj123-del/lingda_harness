# Agent Note: 工具携带与调用命中指标

Status: implemented

[English](2026-09-16-tool-usage-metrics.md) | 中文

## Problem

仅统计调用总数，无法定位反复发送给模型却很少被选择的工具。把目录规模当成执行次数，也会掩盖输入开销的来源。

## Decision

现有工具统计读取器使用最近请求头重建原生工具目录，并为每条已结束的 assistant 消息或尝试中的每个工具增加一次携带计数。请求头只记录变化，因此仅统计请求头事件会漏掉重复请求。继承前缀用于建立目录状态，但不增加携带计数。缺少请求头会单独报告；显式空目录仍是已知目录。

每个携带工具且产生对应直接调用的请求，为该工具贡献一次命中。匹配使用响应中的调用标识、工具名、轮次和步骤。重复调用会增加调用总数，但只贡献一次命中。PTC 内部调用保留独立计数。压缩摘要和进行中的请求不计入。

工具页面显示携带次数、命中次数、命中率和请求数，支持按携带次数及命中率升序排序。汇总描述全部保留会话，不受卡片筛选影响。无携带记录时显示破折号。指标不改变请求，也不会自动禁用工具。

## Alternatives considered

**调用次数除以请求数。** 重复调用可能超过 100%，且内部调用不一定出现在原生目录中。按匹配请求去重，才能回答被携带的工具是否使用过。

**持久化新的指标事件。** 现有保留事件支持历史重新计算，无需增加持久化格式或另一份可变真源。

## Consequences

低命中率是复查依据，不证明工具不必要，也不证明其定义 Token 会全额计费。结果取决于保留日志；无法读取的会话与缺失目录都会明确显示。聚合命中率先汇总命中数和携带数再计算比例，不直接平均百分比。该指标衡量选择情况，不衡量成功率或任务质量。

单元测试覆盖重试、重复调用、请求头变化、继承状态、缺失目录和 PTC 分离。组件与录制会话浏览器测试验证汇总与单工具数值、排序、刷新和窄屏展示，不调用模型。
