# Agent Note: 手机扫码访问

Status: implemented

[English](2026-09-23-phone-qr-access.md) | 中文

## 问题

Web 界面只接受运行它的那台机器的连接，`--mobile` 也只能到达同一受信任网络里的手机。要在另一张网络上的手机使用 DSH，就需要一个公网地址；而免费 ngrok 主机名要等隧道起来才分配，浏览器信任名单又在进程启动时就固定了。

## 决策

`packages/webhook/phone-access` 为正在运行的 Web 端口打开一条 ngrok 隧道。Web 组合装入它，浏览器在 `settings.integration.item` 上、飞书卡片正下方注册一张**手机访问**卡片，位置是**设置 → 连接服务**。

authtoken 是凭据引用 `DSH_NGROK_AUTHTOKEN`。它不进入设置文档、参数列表、日志或二维码内容，只通过 `NGROK_AUTHTOKEN` 环境变量交给 `ngrok`。生成二维码会先关掉本进程已有的隧道，启动 `ngrok http <端口> --log=stdout`，再从 `http://127.0.0.1:4040/api/tunnels` 读取第一条 `https` 隧道。扫码地址是这个源加上本进程的启动令牌，由 `connection.authenticatedUrl` 生成，因此令牌只交给已经登录的浏览器。卡片同时给出 `dsh web --trusted-host <主机名>`，并说明先退出 DSH、运行这行、等它起来后再扫。

隧道在 fiber 释放时结束。本进程从不重启自己：重启会关掉隧道并换掉免费主机名。

## 考虑过的替代方案

### 为什么不在终端打印二维码？

需求是在手机上扫码，并且要在**设置 → 连接服务**、飞书那一行下面找到这个入口。终端里的二维码在用户打开的设置页上看不到。

### 为什么不由卡片重启 DSH？

重启会换掉进程，隧道随之关闭，免费主机名也会重新分配，刚打印出来的地址立刻就失效了。信任名单在启动时采样一次，所以卡片只打印重启命令，重启交给用户。

### 为什么不用付费固定域名或中继？

付费保留域名和 ZCode 式的中继都要额外的账号和服务，这个部署没有。免费档加上每个新主机名重启一次，覆盖了提出的场景。

## 后果

不在本地网络的手机可以打开界面，代价是安装 ngrok，并且每次扫码前重启一次 DSH。一个进程只持有一条隧道，两个进程不能共用本机检查接口。二维码内容是该进程的登录钥匙；卡片写明不要把它发给别人。
