# Agent Note: Plugin inventory browsing categories

Status: implemented

English | [中文](2026-09-15-plugin-inventory-categories.md)

## Problem

插件列表之前只按作用域展示长列表。搜索可以查找明确的关键词，但用户无法按能力浏览相关插件，例如 Skill、RAG 和常用 Tool。

## Decision

插件清单页面增加分类栏，同时保留原有的会话插件和全局插件作用域。分类包括全部、Skill 与工作流、RAG 与知识库、Tool 常用工具、Agent 与协作、模型相关、系统与会话、外部集成和其他插件。文生图和语音模型插件会归入模型相关分类。当前分类会与已有搜索词叠加。

插件外壳注册 key 为 `plugins` 的 `main` 页面，保留 `settings.plugins.tab` 扩展点用于清单和配置标签页。产品导航直接选择该页面，设置弹窗不再包含插件分区。全局页面隐藏会话列表，同时保留列表宽度偏好与当前会话。

分类器使用每条清单已有的模块名和条目 id。它依次检查外部集成、RAG、Skill 与工作流、Agent、模型相关、Tool 以及系统关键词；模型相关关键词包含文生图和语音模型标识符，无法匹配的插件归入其他插件。这个顺序可以避免带有 `feishu`、`mcp`、`rag`、文生图或语音模型关键词的插件被通用的 `tool` 关键词提前归类，而且不需要为自定义插件改动 Remote 数据结构。

## Alternatives considered

**在 Host inventory Remote 中增加分类字段。** 本次浏览体验改进没有采用这个方案，因为现有自定义插件不会发布分类元数据，修改共享快照会要求所有生产者和消费者一起迁移。当前标识符已经足以提供有用的第一层分组。

**用分类替换会话插件和全局插件。** 没有采用，因为作用域和能力回答的是两个不同问题。界面保留两个作用域分组，并在分组内应用分类。

**只使用自由文本搜索。** 没有采用，因为用户需要在不知道模块名称时按大致能力发现插件，尤其是插件数量较多时。

## Consequences

- 分类数量对应当前预设行加全局行，并随搜索结果更新。
- 包含 `feishu`、`lark`、`mcp`、`rag`、`embedding` 和 `knowledge` 等关键词的自定义标识符无需改包即可进入相应分类。
- 分类仍然是界面展示启发式。未来如果增加插件元数据协议，可以替换或细化分类逻辑，而不需要改变分类筛选交互。
- 窄屏下分类栏换行，用户创建的条目排在预设与全局分组之前。
- 独立页面使用主内容区宽度和响应式卡片网格，不再受设置弹窗窄内容列限制。
