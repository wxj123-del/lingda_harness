# Agent Note: 会话工作流视图

Status: implemented

[English](2026-09-20-workflow-view.md) | 中文

## 问题

对话页头提供了详细的 Trajectory 记录表，但读者需要自行从记录表还原模型步骤、工具调用、嵌套调用和结果之间的因果链。需要一个紧凑的概览，帮助用户在打开记录详情前理解当前会话。

## 决定

Trajectory 客户端插件在现有 `trajectory` 视图旁注册本地化的 `workflow` Conversation 视图。它把驻留的 Trajectory 快照投影为相互连接的卡片，展示输入、模型步骤、工具调用、嵌套调用和结果。点击工具或结果卡片会在工作流内打开独立详情面板，展示参数、结果、错误和嵌套调用，因此不会跳转到 Token 轨迹。进行中的调用会显示明确的运行状态；缺少结果时不会推断为成功。

投影只在客户端读取现有会话快照，不增加会话事件、模型可见字段、持久化记录或新的工具执行行为。视图对参数和内容使用有界单行预览，完整载荷仍由 Trajectory 检查器负责展示。

## 考虑过的替代方案

**在记录表上方增加工作流区段。** 否决，因为记录表与概览的扫描目标不同；独立视图可以保持现有高密度检查界面不变，并为工作流链路提供足够的纵向空间。

**增加第二套事件或持久化投影。** 否决，因为 Trajectory 已经配对工具调用、结果、嵌套调用和运行状态。第二套投影会重复生命周期逻辑并产生第二个事实来源。

**只显示顶层工具调用。** 否决，因为嵌套 PTC 调用是理解执行链路所需的信息；嵌套调用会按调度顺序显示在父级结果下方。

## 后果

对话视图环新增 `工作流` / `Workflow` 标签页。概览有意只覆盖已加载的 Trajectory 窗口，因此更早且尚未加载的历史需要先通过现有 Trajectory 分页路径加载。工具卡片支持点击与键盘操作；选中后在当前工作流内展开详情面板，主链路仍保持可见。对于仍在运行或其结果不在驻留窗口内的调用，视图不会虚构输出。
