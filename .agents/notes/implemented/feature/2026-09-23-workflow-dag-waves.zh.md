# Agent Note：工作流 DAG 执行波次

Status: implemented

[English](2026-09-23-workflow-dag-waves.md) | 中文

## Problem

可视化编译器虽然校验 DAG，但之前仍在一个顺序拓扑循环中执行所有节点。相互独立的分支无法并行，而且汇聚节点可能在循环中先遇到的任一入边到达时就开始。

## Decision

将图编译为依赖波次。每个波次使用 `Promise.allSettled` 执行彼此隔离的节点任务，只有当前波次的所有前置任务结束后才会开始下一波；随后第一个拒绝结果会使运行失败，并且不会启动下游波次。条件分支仍由 active edge 状态控制。汇聚节点在依赖波次结束后只要有至少一条入边处于 active 就会启动，输入数组包含所有已经产生的前置值；这是 OR 汇聚，而不是要求所有分支都到达的 AND 栅栏。最终结果从唯一的结束节点读取，不再依赖并行任务之间的写入顺序。

## Alternatives considered

**使用 `Promise.all` 立即拒绝整个波次：** 否决，因为脚本已经失败后同波次节点仍可能继续运行，导致审计和清理时序不确定。

**部分波次失败后继续执行下游节点：** 否决，因为下游输入不完整，已知失败的运行仍可能产生副作用。

## Consequences

独立的模型、工具、知识库、代码和 HTTP 子任务可以在 Host 工作流上限与 PTC 并发上限内重叠执行。失败波次会先等待同波次任务结束再失败，因此活跃节点审计可以确定性地结束；拒绝后不会执行下游波次。分支汇聚具有确定的前置完成语义；普通子 agent 失败继续保持现有的 `null` 结果语义。循环仍由图校验拒绝。

## Validation

UI 编译器测试通过 DAG 并行波次与汇聚断言，以及重试、分支和工具隔离覆盖。UI Layout TypeScript 检查通过。
