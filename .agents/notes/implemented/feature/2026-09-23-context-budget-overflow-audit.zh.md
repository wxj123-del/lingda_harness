# Agent Note: 上下文预算超限审计与确认语句路由

Status: implemented

[English](2026-09-23-context-budget-overflow-audit.md) | 中文

## Problem

系统提示词、当前用户消息和持久检查点等强制消息可能超过有效请求预算。选择器必须保留这些必要内容，但如果没有明确审计，界面无法区分已受预算约束的请求和不可避免的超限请求。简短确认语句也不包含任务关键词，原先可能被判定为新话题。

## Decision

`ContextSelection` 和持久化的 `context/router` 事件在最终工具配对闭合后记录 `budgetExceeded` 与 `overflowTokens`。可选消息会按类型分类，预算紧张时优先保留任务相关的用户消息和模型输出；被动插件上下文默认额外限制在消息预算的 25% 以内，当前开放 turn 的工具工作集保持优先级但仍受总预算约束。当 Session 存在持久化的任务生命周期事件时，任务继续指令会召回最近任务的模型可见消息，并记录对应的 `taskId` 和召回数量。事件还可记录包含工具 schema 的 `estimatedRequestTokens` 总量、包含输出预留的 `estimatedWindowTokens`，以及完整请求包超过模型窗口时的 `requestOverflowTokens`，同时记录每条消息的有限类型、Token 和截断预览元数据。元数据最多包含 128 条选中消息，并记录被省略的数量；它不复制完整消息正文。Token 轨迹详情在必要内容超过有效消息预算或完整请求包超过提供方窗口时显示本地化警告。当存在全局路由审计时，personal-agent 分项会标记为策略预处理，路由审计作为最终请求快照；预览优先使用有限的最终消息元数据。持久消息与工具结果裁剪或重复上下文替换不一致时，预览会显示提示。provider runtime 现在会在文件或图片投影后发出 adapter-ready 边界；当投影改变消息时，路由器会追加有界的 `finalPayload` 审计，让预览显示提供方可见的投影结果。路由器在关键词匹配前识别简短确认和继续指令，将它们路由到任务上下文；整个过程不调用模型或 embedding。当开放 turn 中存在无法放入预算的工具单元时，不再用更早轮次的候选消息回填剩余预算。路由器重启后会从持久化的 turn 和用户消息事件恢复开放 turn 的边界。

## Alternatives considered

**丢弃必要消息以满足预算。** 放弃，因为删除当前请求或系统提示词可能导致提供方请求无效，或改变任务约束。

**静默依赖提供方处理超限。** 放弃，因为请求审计和上下文预览会显示已受预算约束，而提供方实际可能拒绝请求。

**把所有无关键词的短句都视为近期上下文。** 放弃，因为空文本或通用短句仍不足以可靠关联无关对话；只有保守的确认词表会被提升为任务上下文。

## Consequences

预算超限现在可见且可量化，同时必要消息仍然保留。路由策略继续保持确定性和本地执行。警告使用固定 token-meter 启发式估算，因此不同提供方分词器造成的差异仍是已知风险。确认词表可能需要根据真实对话样本继续扩充。
路由器还会按不可变消息和请求 header 的身份缓存 token 估算，因此同一条长工具链不会在重复选择和审计阶段被反复计量。
因此，开放 turn 在预算紧张时可能保留更少的总消息，但会优先保留当前工具工作集，而不是填入旧历史的小消息。
浏览器现在可以区分策略预处理和最终路由请求。有限元数据让变换后消息的预览可检查，同时不复制完整正文，但它仍然是有界预览，不是逐字节等同于提供方 payload 的副本。
持久任务召回按 live Session 建立索引，并从事件序列水位线开始增量折叠。第一次查询仍会回放已有日志以保证重启后正确恢复；重复请求不再扫描完整 transcript。召回 ID 受 `taskMessages` 限制，因此简短确认不会扩展为整个上一任务的 transcript。在 `turn/end` 清除当前 turn 后续事件的归属，可以避免把新事件错误归入旧任务，同时保留生命周期记录供后续任务延续召回。
