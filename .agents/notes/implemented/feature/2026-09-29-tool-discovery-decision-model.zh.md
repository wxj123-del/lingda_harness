# Agent Note：仅使用本地决策模型排序工具发现结果

Status: implemented

[English](2026-09-29-tool-discovery-decision-model.md) | 中文

## 问题

大型原生工具目录需要语义能力匹配，但如果用建议性模型替换授权或执行控制，工具使用就会依赖不受信任的服务，并可能扩大权限范围。

## 决策

`@deepseek-ai/dsh-tool-discovery` 接受显式的 `decisionModel` 配置，并把经过权限过滤的能力候选发送到 `POST <url>/decide`。服务返回带置信度和可选概率的类型化 `capability` choice；接受的候选沿用现有发现结果，只有在工具结果持久提交后才会变为可见。

决策模型是受 `timeoutMs`、`candidateLimit`、`searchLimit` 和 `resultMaxBytes` 限制的建议组件。完整名称匹配仍然是确定性的。响应无效、选中项置信度过低、请求超时或网络失败时使用词法排序。现有工具限制、审批、参数校验、执行超时和并发限制仍是权威规则，不委托给模型。

## 备选方案

**让决策模型负责审批或执行策略。** 拒绝，因为模型输出不是授权来源，服务故障或提示词操纵不能改变调用方权限。

**无条件替换词法发现。** 拒绝，因为本地服务可能不可用、变慢或校准不准；确定性的回退路径可以保持发现功能可用且可复现。

**把完整目录发送给服务。** 拒绝，因为候选上限属于提示词和延迟预算的一部分，而且必须在模型输入前完成权限过滤。

## 后果

当预设选择启用本地服务时，中文或其他非词法能力请求可以使用决策模型。每次此类搜索都会增加一次有界的本地请求，并可能加载不同的 schema，同时承担对应的提示词缓存和延迟成本。`standard` 与 `diaosi` 随附预设已配置 `http://127.0.0.1:8000`；服务由 `scripts/start-decision-model.sh` 单独启动，服务不可用时会回退到词法排序。

## 验证

工具发现行为测试覆盖类型化排序、词法回退、持久激活、权限过滤和有界目录恢复。该包的 TypeScript 检查通过。
