# Agent Note：本地多知识库

状态：已实现

[English](2026-09-16-local-knowledge-base.md) | 中文

## 问题

原来的知识库区域把纯文本保存在 `ui-authoring` 中，并使用子串搜索，不能隔离多个知识库、选择切分策略，也不能对中文内容进行语义检索。

## 决策

增加由 Host 负责的 `knowledge` service。可编辑清单使用乐观版本和原子替换。LanceDB 为每个已提交索引保存一个轮换表，因此重建索引不会暴露混合版本。`Xenova/bge-small-zh-v1.5` 通过 ONNX CPU 推理按需加载。递归、Markdown 和固定长度切分共用一套预览与建索引逻辑。Web 页面管理知识库和知识内容、预览片段、显示模型与索引状态，并测试检索。`knowledge_list` 和 `knowledge_search` 是面向智能体的工具。

Web 页面首次打开时导入旧的 `ui-authoring.knowledge`，但不修改原设置。检索返回原文片段、来源、片段序号和余弦相似度；尚未完成索引的知识库会明确列在 `skippedBases` 中。

## 影响

建索引和向量化在本机完成，不消耗服务商 Token；模型请求携带工具定义和检索片段时会增加上下文 Token。首次使用需要联网下载模型。数据目录预期由一个 Host 进程使用。片段大小按字符计算，相似度不是校准后的概率。

## 验证

知识库包、Remote 组装和 layout 包通过 TypeScript 工程检查。Chrome 在 3081 端口实测了两个知识库、多篇中文知识、三种切分预览、模型下载、LanceDB 建索引、语义检索、刷新持久化和删除。390px 窄屏没有横向溢出。6 项切分与界面测试、1 项知识库 Loader 组合测试及定向 lint 通过。组合测试仅替换外部向量推理和聊天提供方，记录了工具发现、知识库列表、原文检索，以及原文进入下一次模型请求的结果。线上对话提交受到另一 Host 持有当前会话写锁的影响。更广的预设测试在并行修改前通过了 36 项；最近一次运行通过 35 项，另有 2 项屌丝模式提示词与 Skill 预期失败，不属于知识库改动。

删除 Remote 使用 `deleteBase`，避开 Client 服务保留的 `remove` 方法。存在启用的知识库时才注册检索工具，最后一个知识库停用或删除后移除工具。
