# Agent Note：个人本地 Agent 工作台控制

状态：已实现

[English](2026-09-20-personal-agent-workbench.md) | 中文

## 问题

现有 Agent 界面需要在不让 UI 与运行时插件重复制定策略的前提下，统一表达个人模式、上下文边界、本地召回、工具发现和工作区证据。

## 决策

个人 Agent 模式、请求级 Context Budget、本地知识库召回预算、有界工具发现和只读 Git 检查点通过现有 DSH 会话事件与插件扩展点组合。模式策略同时过滤模型可见工具，并在执行层执行相同限制；在用户选择个人模式之前，旧 preset 会话保持原有工具行为。

上下文组装在加入最近历史、召回内容和工具结果之前，先保留系统指令与当前用户请求。系统会裁剪过大的工具结果、标记重复上下文，并在 `agent/request-context` 中记录系统、工具 schema、历史、知识库和工具结果的估算 Token。知识库召回应用相似度阈值、正文去重、结果数量限制和估算 Token 上限。工具发现记录选择原因，查询无命中时可以恢复配置的安全工具集合。

编码轮次前后会采集有界的 `git status`、分支、差异统计和差异文本。Token 轨迹将这些事实显示为只读 Git 工作区视图，包括文件状态、统计数字和可展开的差异文本；系统不会修改 Git，也不会自动提交。

## Alternatives considered

把每项预算和证据策略分散在各自的 UI 或工具插件中会为同一请求产生竞争决策；新增独立编排服务也会重复现有 Session 事件和插件扩展点，因此均未采用。

## 影响

轨迹可以解释请求上下文和工作区变更，但不会把估算值当作提供方账单。当裁剪当前用户请求或系统指令会丢失必要事实时，硬性上下文预算允许保留超出估算上限的单条消息。知识库和工具发现控制可以减少无关上下文，但可能需要后续搜索或再次召回。Git 证据有大小上限，较旧的差异行可能被省略。

单元测试覆盖当前请求保留、知识库结果选择、工具发现原因与恢复、Git 投影和既有轨迹行为。Cordis 与持久化目录已根据源码重新生成。
