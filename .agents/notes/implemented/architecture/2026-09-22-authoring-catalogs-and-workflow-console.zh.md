# Agent Note：内置创作目录与工作流操作台

Status: implemented

[English](2026-09-22-authoring-catalogs-and-workflow-console.md) | 中文

## 问题

Skill 页面虽然展示内置指令，却要求用户手动重建。工作流页面使用通用编辑器，用户没有模板发现、一键导入或用于维护有序步骤的专门位置。

## 决策

内置内容继续使用类型安全且由 locale 管理的模板，并把导入后的副本保存到已有的 `ui-authoring` 设置命名空间。Skill 目录为内置项提供一键导入，并用稳定 id 避免重复卡片，同时保留用户后续编辑。工作流页面改为专门的模板库操作台，提供搜索、来源筛选、三个确定性的测试模板、一键导入和可视化编辑器。编辑器保存节点位置和有向连接，支持拖拽、从节点面板添加节点、连接点、启用状态和属性检查器；同时从画布图生成旧的有序指令列表，保持现有运行时工具兼容，并使用已注册工作流工具名把任务带入输入框。

运行时继续把已启用的用户工作流注册为说明工具。客户端不直接调用仅由 Host 持有的工作流引擎；启动工作流时复用既有会话输入路径组合模型可见请求，由工具路径负责执行和记录会话。

## 已考虑的替代方案

**继续使用通用编辑器。** 否决，因为它隐藏了可复用示例，并要求用户先理解持久化数据模型。

**从浏览器调用工作流引擎。** 否决，因为引擎由 Host 持有，浏览器直接调用会重复执行与生命周期策略。

**把导入模板设为只读卡片。** 否决，因为用户需要根据本地指令和约束调整测试工作流。

## 影响

内置 Skill 和工作流现在都有明确的发现与导入入口，导入后的模板可编辑且不会改变内置默认值。操作台是本地功能，不访问远程商城；以后增加模板需要同时增加本地化模板定义和运行时内容。客户端组件测试覆盖了这些交互，包文档记录了模板、导入和编辑模型。
