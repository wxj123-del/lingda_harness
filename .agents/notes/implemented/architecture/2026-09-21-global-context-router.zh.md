# Agent Note：全局上下文路由器

[English](2026-09-21-global-context-router.md) | 中文

状态：已实现

## 问题

持久化 Session 会随着长任务增长，但简单的新问题不需要把之前所有用户、助手和工具消息都发送到下一次模型请求。

## 决策

基础组合在共享的 `agent/request-context` waterfall 上挂载 `@deepseek-ai/dsh-context-router`。路由器在其他上下文监听器运行后选择请求快照。每轮第一步根据确定性的请求措辞选择 `fresh`、`recent`、`task` 或 `full`；后续步骤优先保留开放 turn 的工作集，再处理较旧历史。如果超过 Token 预算，会先原子地裁剪较旧的工作集单元，再裁剪更旧的轮次历史。系统消息和最新用户消息始终必需，工具调用与结果按配对保留或丢弃。追加式 Session 日志仍是事实源，每次选择都会记录诊断用的 `context/router` 事件。

## 曾考虑的替代方案

**先使用 embedding 检索。** 暂缓，因为在基本请求快照契约得到验证前，它会增加索引、模型或提供方依赖以及非确定性排序。

**在路由时删除或压缩 Session 历史。** 否决，因为这样回放和审计会依赖后续请求的措辞。压缩仍是独立的持久化操作。

## 影响

简单问题现在使用有界的近期快照，明确的任务延续可以召回旧的关键词匹配消息，完整历史请求仍可在配置预算内使用。多步骤工具任务不会在每次模型调用时都被重新分类为新请求。路由刻意采用保守的词法规则；语义检索和更丰富的任务记忆索引留作后续工作。
